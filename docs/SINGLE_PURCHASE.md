# 单次代付流程与接入

## 当前实现与实际执行边界

本次增加可运行的授权与人工操作模块。客户收款仍只支持 offline / stripe_test；没有启用真实银行卡扣款，没有自动登录第三方账号，也没有自动控制第三方订阅或卡片。所有平台内动作由操作员实际执行后逐步确认，API 和页面明确标识 `operator_attestation_not_provider_verified`。只有人工确认全套步骤后，流程才为 completed；这与客户订单 paid 是独立状态。

当前目录仅有明确标识的测试商品，不能直接用作真实会员报价。接入 SmartChatVip 正式商城之前，需要把真实的商品与订单价格快照、已验签收款结果、站点用户身份和操作员身份绑定到该流程。不能以离线模拟付款为依据处理真实订单。

## 启用与走通

1. 在仓库根目录 `.env` 设置 `OPERATOR_TOKEN` 为独立的随机长密钥，至少 32 字符。可运行 `python -c "import secrets; print(secrets.token_urlsafe(32))"` 生成，自行保存；不要放进 VITE 环境变量。API 重启后生效。留空时操作后台、授权创建和凭据提交均关闭。
2. 按 README 启动 API 与前端，或 `docker compose up --build -d`。Compose 已透传操作员密钥，同时运行 beat 与 worker。
3. 创建测试订单、完成模拟付款，在订单下方阅读单次授权并明确勾选。授权版本 single-purchase-session-v2，有效期 24 小时，不能通过重复提交重置或延长。新的购买应重新下单授权。
4. 可以与操作员配合现场登录；也可通过独立表单提交本次授权的 Session 文本（令牌或 Session JSON）。不再收集账号密码、银行卡号、CVV 或一次性验证码；Session 的提交与保存不会验证其有效性或自动建立第三方登录。
5. 页面底部打开操作后台，输入操作员密钥，加载授权订单。密钥只放在当前组件内存，不写入 localStorage/sessionStorage。
6. 如有临时凭据，可一次性领取；服务端先提交数据库删除，再返回明文。网络中断也不回滚删除，须由用户重新提交。界面显示最长 60 秒，切换标签页、切换订单、退出后台或确认步骤会清除组件中的显示值。仍须由操作员完成实际浏览器会话清理。
7. 按下面顺序实际操作，每步填写外部凭证编号并确认：

| 步骤 | 实际核对内容 |
| --- | --- |
| login_confirmed | 登录账号正确，并核对订单授权范围 |
| membership_active | 指定套餐付款成功、会员到账，记录交易凭证 |
| renewal_cancelled | 自动续费关闭；核对权益到期结束，避免误点立即失效 |
| payment_method_removed | 本次付款银行卡已从账号移除 |
| logged_out | 已退出账号并清除操作环境内的浏览器登录资料 |
| completed | 当前数据库无临时凭据，核对前述步骤后完成交付 |

无法取消续费、移除付款方式或确认退出时，不勾选完成，保留待处理并联系用户。不要为了结束订单伪造确认。凭证编号仅允许字母、数字、下划线和连字符；截图或收据内容由外部业务系统保管，不要将Session、卡号等填入编号。

## 暂停与恢复

操作员可对仍在授权期内且尚未完成的订单选择原因并暂停交付。暂停会立即删除本系统在线数据库中的暂存 Session，阻止再次上传或领取凭据，也阻止登录、会员购买和最终完成确认。暂停本身不会自动退款、撤销已发生的外部购买或重试付款。

只有流程已经执行到取消续费、移除付款方式或退出账号阶段时，才允许在暂停中继续按顺序记录对应清理步骤；不能用清理操作跳过登录或会员购买步骤。最终 `completed` 仍须先恢复，且完成前不得存有临时凭据。

问题处理完后，操作员可恢复仍处于有效授权期内的暂停订单。恢复不会延长原来的 24 小时授权截止时间、恢复已删除的 Session 或自动重试付款；仍需登录时由用户重新提交。重复暂停／恢复返回 409，已完成、已撤回或授权过期的订单不能暂停或恢复。暂停原因只在当前状态为 `paused` 时展示，撤回、过期、恢复或完成后不保留为当前状态提示。

并发暂停使用订单工作流版本进行 CAS 防护：只有一个请求成功，另一个返回 409，并且只记录一条暂停事件。工作流保存采用严格递增时间戳，避免同一数据库时钟精度下暂停与恢复事件顺序不确定。

## 撤回授权与清理

用户可以撤回尚未执行的授权，并立即删除在线数据库内暂存的登录信息。撤回和 24 小时授权过期都会阻止后续登录领取、凭据上传、付款确认和订单完成；仍允许操作员记录取消续费、移除付款方式、退出账号这些清理操作。跳过的购买步骤不会被伪造为完成。撤回不会自动撤销已经发生的外部购买或进行退款，操作员须另行处理售后；界面保持“需清理与售后”。

临时 Session在独立 manual_fulfillments 表内 Fernet 加密，最长暂存 15 分钟；一次性领取、用户主动删除、撤回或超时后移除密文。beat 每分钟调度既有过期清理任务；访问流程与操作接口时也执行补充清理。若 API、worker 和 beat 全部停止，不能声称 15 分钟一到就已物理删除；重启清理后生效。凭据过期后不能被领取，即使定时器晚执行。

删除范围是本系统在线数据库中的凭据字段。数据库备份、SQLite WAL/空闲页、宿主机快照、代理请求日志、操作员浏览器和剪贴板不能因此宣称已擦除。部署时禁止记录这些请求的 body；备份与快照应排除临时凭据或具备单独的保留/清理政策。人工后台只以确认记录表示外部浏览器清理，本系统无法远程证明操作员机器无残留。

## 接口

| 接口 | 身份与作用 |
| --- | --- |
| GET /fulfillment-policy | 公开授权版本、全文、有效期与是否已配置操作后台 |
| POST /orders/{id}/consent | 订单 Bearer；version 与 accepted:true，须已确认测试付款 |
| GET /orders/{id}/fulfillment | 订单 Bearer；授权与人工交付进度，不含 Session 明文 |
| POST /orders/{id}/login-credential | 订单 Bearer；credential_type:"session"、session，限授权期间且会员付款确认前 |
| DELETE /orders/{id}/login-credential | 订单 Bearer；删除在线数据库凭据 |
| POST /orders/{id}/revoke-consent | 订单 Bearer；撤回授权并删除暂存凭据 |
| GET /operator/orders | 操作员 Bearer；最近 100 笔授权订单与商品价格 |
| POST /operator/orders/{id}/reveal-credential | 操作员 Bearer；领取一次即删除，再次领取返回 409 |
| POST /operator/orders/{id}/attest | 操作员 Bearer；action、confirmed:true、evidence_ref，严格步骤检查 |
| POST /operator/orders/{id}/pause | 操作员 Bearer；reason，暂停有效未完成订单并删除暂存凭据 |
| POST /operator/orders/{id}/resume | 操作员 Bearer；恢复有效暂停订单，不延长授权或还原凭据 |
| GET /operator/orders/{id}/audit | 操作员 Bearer；授权、领取、暂停／恢复、清理和确认日志，不含凭据 |

凭据仅允许 HTTPS 提交（本地开发回环地址除外）。公网反向代理须正确终止 TLS、传递可信的协议头，且 API 仅绑定回环；不要信任任意外网客户端传入的 X-Forwarded-*。服务响应带 Cache-Control:no-store。生产身份接入应替换共用操作员密钥为具备个人身份与权限的管理后台。

## 数据和验证

在原测试模块数据库中新增独立表，不改写旧 orders 字段、不删除现有订单。旧研究原型的 orders 表依旧按原逻辑拒绝不兼容结构，需要先按 INTEGRATION.md 迁移。授权和操作记录保留商品、金额与币种快照的引用及授权版本；它们用于售后审计，不包含 Session 明文。

测试覆盖：未付款拒绝授权、明确同意与版本、用户/操作员权限隔离、严格顺序、未清凭据禁止完成、加密与单次领取、定时清理、授权撤回/过期、请求校验不回显凭据、未配置后台时关闭入口，以及暂停原因校验、凭据删除、上传／领取／购买／完成阻断、清理阶段边界、恢复语义、重复操作、撤回／过期后禁止恢复、同时间事件排序与并发暂停 CAS。

2026-11-15 本地实际执行：SQLite 后端 `62 passed`，前端 `npm run build` 通过；离线浏览器走通创建订单、模拟付款、授权、Session 提交、暂停和恢复，核对暂停原因、凭据删除、入口阻断及恢复后无残留原因。PostgreSQL、Compose、真实 Stripe 与真实会员交付未在本次执行中验证，以对应环境中的实际结果为准。

## Session 凭据格式调整

POST /orders/{id}/login-credential 接收 JSON：`{"credential_type":"session","session":"<本次授权的 Session 文本>"}`。Session 按不透明字符串处理，上限 32768 字符，拒绝空白值；不解析或执行 Session JSON 内的 URL、脚本或命令，也不调用其提供的地址。领取接口仅返回 credential_type 和 session，不再返回账号或密码。校验错误不回显输入，查询、队列与审计记录不包含 Session 内容。前端不把 Session 写入浏览器存储，提交请求结束或标签页隐藏时清除输入。

授权版本调整为 single-purchase-session-v2。旧版授权不能用于 Session 提交、领取或购买确认，仅允许清理；请为新购买创建新订单并明确同意新版本。数据库无需改列，旧的加密字段继续使用；旧版账号密码密文不会被作为 Session 返回。

从数据库删除 Session 不等于让第三方平台上的 Session 失效。账号内的退出登录、撤销会话和操作环境清理由操作员实际执行并记录，本模块没有会话撤销 API。
